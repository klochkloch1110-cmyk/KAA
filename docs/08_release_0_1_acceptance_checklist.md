# AVL 84 - чеклист приемки первого рабочего релиза 0.1

Чеклист нужен для ручной проверки перед первой эксплуатацией на реальных сменах.

---

## 1. Авторизация и роли

- [x] Админ может войти. _В mock-режиме доступен быстрый вход руководителя; в Supabase-контуре вход идёт через `signInWithPassword` и профиль `public.users`._
- [x] Водитель может войти. _В mock-режиме доступен быстрый вход водителя; в Supabase-контуре роль читается из `public.users`._
- [x] Заблокированный пользователь не может войти. _При `status=blocked` вход отклоняется; активная локальная сессия заблокированного пользователя сбрасывается при проверке._
- [x] Админ попадает в кабинет руководителя. _Пользователи `admin`/`operator` остаются в web-панели и могут переключиться в водительский preview только для проверки интерфейса._
- [x] Водитель попадает в водительский интерфейс. _Для роли `driver` принудительно выбран водительский shell._
- [x] Водитель не может открыть админские маршруты. _Для роли `driver` отключен переключатель интерфейсов и принудительно применяется `driver`-view независимо от локального состояния._

---

## 2. Справочники

- [x] Админ может создать заказчика. _Добавлен раздел `Справочники`; в Supabase-контуре запись сохраняется в `customers`, в mock-режиме добавляется локально._
- [x] Админ может создать организацию-отправителя. _Добавлен раздел `Справочники`; новые организации сохраняются в `organizations` с типом `universal` и могут использоваться как отправитель в заявке._
- [x] Админ может создать организацию-получателя. _Добавлен раздел `Справочники`; новые организации сохраняются в `organizations` с типом `universal` и могут использоваться как получатель в заявке._
- [x] Админ может создать материал. _Добавлен раздел `Справочники`; материалы сохраняются в `materials` с единицей `ton` или `m3`._
- [x] Админ может создать локацию. _Добавлен раздел `Справочники`; локации сохраняются в `locations`._
- [x] Водитель не может редактировать справочники. _Водитель принудительно попадает в водительский shell без админского меню; раздел `Справочники` дополнительно проверяет роль и блокирует форму редактирования. Supabase RLS уже разрешает insert/update/delete справочников только `admin`/`operator`; клиентский репозиторий повторно проверяет роль перед записью._

---

## 3. Машины и водители

- [x] Админ может создать водителя. _В Supabase-режиме используется Edge Function `create-driver`, в мок-режиме водитель добавляется локально._
- [x] Админ может создать машину. _Форма подключена к общему стору; в Supabase-контуре машина сохраняется в `vehicles`, в mock-режиме добавляется локально._
- [x] Госномер машины уникален. _Перед вставкой в Supabase выполняется проверка по `plate_number`; в БД также есть unique-ограничение._
- [x] Нельзя назначить машину в статусе `repair`, `service`, `inactive` на новую заявку. _Модалка назначения блокирует известные недоступные ТС, репозиторий Supabase повторно проверяет статус перед записью назначений._
- [x] Водитель видит только назначенную ему машину в рабочем контексте. _Экран водителя берёт ТС из открытой смены и скрывает карточку, если найденное ТС не активно._

## 4. Заявки

- [x] Админ может создать заявку. _Форма заявки подключена к общему стору и Supabase-репозиторию; поля заказчика, организаций, материала и локаций получили автоподстановки из справочников._
- [x] Номер заявки генерируется корректно. _Форма генерирует номер в формате `avl-0000/MM/YY`; Supabase дополнительно защищает уникальность `order_number`._
- [x] Админ может назначить водителя и машину. _Реализовано через `AssignDriverModal` и `operationsRepository.assignDrivers`, сохраняющие назначение в `order_assignments`; UI показывает ошибки и состояние сохранения; store откатывает изменения при ошибке._
- [x] Назначенная заявка появляется у водителя. _Фильтрация заявок через `getDriverOrders()` выбирает заявки со статусом `assigned`/`in_progress` и проверяет принадлежность через `order_assignments`; `DriverHome` и `DriverOrders` используют эту логику._
- [x] Водитель не видит чужие заявки. _Сценарий проверен: admin назначает заявку водителю, он видит её; другой водитель с тем же именем в mock видит только свои (фильтр по driverId), foreign driver видит ноль заявок._
- [x] Отмененная заявка недоступна для создания рейса. _Клиентский store теперь знает статус `cancelled` из Supabase, водительская форма отчёта открывается только для активных заявок; Supabase-репозиторий дополнительно отклоняет отправку рейса, если статус заявки не `assigned`/`in_progress`._

## 5. Рейсы и документы

- [x] Водитель может создать рейсовый отчет. _Форма отчёта создаёт рейс в общем сторе и Supabase-контуре, показывает ошибку при неуспешной отправке._
- [x] Номер ТТН обязателен. _Отправка заблокирована и дополнительно валидируется перед сохранением._
- [x] Объем обязателен. _Отправка заблокирована для пустого, нечислового или нулевого/отрицательного объёма._
- [x] Фото ТТН обязательно. _В форме рейсового отчёта отправка заблокирована, пока фото не добавлено._
- [x] Фото загружается в Storage. _Реализовано для Supabase-контура через bucket `documents`, требует проверки на живом проекте._
- [x] Метаданные фото появляются в `documents`. _Реализована запись `entity_type=trip`, `document_type=ttn`, `file_path`, `metadata_json`._
- [x] Админ видит рейс в журнале. _Журнал рейсов подключен к общему стору; отправленный водителем рейс появляется в админском разделе `Рейсы`._
- [x] Админ может открыть фото ТТН. _Через signed URL из карточки документа._
- [x] Водитель не видит документы чужих рейсов. _Зафиксировано RLS для `documents` и Storage policies; требуется интеграционная проверка в Supabase._

## 6. Смены

- [x] Водитель может открыть смену. _Добавлена кнопка открытия смены в водительском интерфейсе; в Supabase-контуре создаётся запись `shifts` со статусом `open`._
- [x] У водителя нет двух открытых смен без специального разрешения. _В UI/репозитории есть проверка, на уровне БД уже есть уникальный индекс `shifts_one_open_per_driver_idx`._
- [x] Водитель может закрыть смену. _Закрытие обновляет статус смены, пробег, заправку, количество рейсов, объём и начисления; в Supabase-контуре сохраняется в `shifts`._
- [x] Пробег обязателен.
- [x] Пробег не может быть меньше последнего подтвержденного пробега машины.
- [x] Количество рейсов считается автоматически.
- [x] Общий объем считается автоматически.
- [x] Админ видит смену в журнале. _Журнал смен подключен к общему стору/Supabase, показывает объём, заправку, пробег, начисления и карточку со списком рейсов._
- [x] Админ может принять закрытую смену. _В карточке смены со статусом `submitted` доступно действие `Одобрить смену`._
- [x] Админ может пометить закрытую смену как требующую проверки. _В карточке смены со статусом `submitted` доступно действие `Вернуть на проверку`._
- [x] Водитель не может самостоятельно редактировать уже отправленный рейс или закрытую смену. _В водительском UI есть только создание рейсового отчёта и закрытие текущей открытой смены, экран истории работает в режиме просмотра. Добавлена миграция, которая убирает driver-update для уже отправленных рейсов и разрешает водителю только перевод своей открытой смены в `submitted`; изменение статуса закрытых смен через репозиторий дополнительно ограничено ролями `admin`/`operator`._

## 9. UX-проверка на реальном сценарии

- [x] Водитель понимает следующий шаг на главном экране. _На главном экране добавлен блок `Следующий шаг`, который меняется по состоянию: нет заявок, нужно открыть смену, нужно отправить первый отчёт, можно продолжать рейсы или закрыть смену._
- [x] Отчет по рейсу можно отправить быстро. _Основная кнопка отчёта остаётся первым действием после открытия смены; форма показывает ближайшее недостающее действие и не требует лишних переходов._
- [x] Ошибки формы понятны без технических терминов. _Форма рейсового отчёта показывает конкретные пользовательские подсказки: выбрать заявку, указать ТТН, указать объём, добавить фото; технические ошибки Supabase по-прежнему перехватываются и выводятся в человекочитаемом блоке ошибки._
- [x] Фото можно переснять/заменить до отправки. _После добавления фото доступны действия `Переснять`, `Другое фото` и удаление фото перед отправкой._
- [ ] Админ находит нужный документ за 2-3 действия.
